## 📝 Completed Task: Lifecycle Board Single Transactions, Skip Policy, and Config Authorisation (BEX-T02)

### 📌 Overview
- **Task Code:** BEX-T02 (BEX-F17, BEX-F18)
- **Branch:** `fix/bex-t02-lifecycle-board-transactions`
- **PR:** #65
- **Description:** Enforce a single atomic transaction per operational lifecycle use case, implement dual approval skip policy enforcement (409 LC_SKIP_DUAL_APPROVAL_REQUIRED for non-admin), validate approver roles against active roles table (422 LC_APPROVER_ROLE_UNKNOWN), and require `users.manage` permission on step configuration updates.

### 📁 Files Changed
- `modules/common/system_messages.py` — Registered `LC_SKIP_DUAL_APPROVAL_REQUIRED` and `LC_APPROVER_ROLE_UNKNOWN`
- `docs/system_message_codes.json` — Regenerated message catalog with new codes
- `modules/lifecycle_board/repository.py` — Replaced mid-transaction commits and refreshes with `db.flush()`
- `modules/lifecycle_board/service.py` — Removed mid-loop commits during prior step reconciliation, added `commit: bool = True` to `advance_lifecycle_step_service`, enforced dual approval skip guard, validated `approver_roles` against DB roles, and unified audit logs into the primary transaction
- `modules/lifecycle_board/router.py` — Added `require_permission("users.manage")` on `PUT /step-configs/{step_code}` and forwarded `actor=current_user`
- `tests/unit/test_lifecycle_board_transactions.py` — New unit test suite (7 comprehensive test cases)
- `tests/unit/test_lifecycle_role_from_token.py` — Updated to align with `users.manage` permission and valid system roles
- `tests/unit/test_step_config_service.py` — Replaced legacy ad-hoc role string with valid system role
- `docs/plans/backend-review/TASKS.md` — Marked BEX-T02 as done (PR #65)

### 📊 Technical Changes
- **Single Transaction Per Use Case**: Converted repository persistence methods to flush only; public service methods (`advance_lifecycle_step_service`, `skip_step_service`, `set_multi_active_stages_service`, `register_pending_reference_service`, `update_step_config_service`, `initialize_file_lifecycle_service`) now execute exactly one single `db.commit()` at completion.
- **Atomic Rollback Guarantee**: Verified that unexpected errors during prior-step reconciliation or SmartTask management roll back completely, leaving 0 activities falsely marked as Completed.
- **Dual Approval Policy**: Steps configured with `skip_policy="dual_approval"` strictly reject non-admin users with 409 `LC_SKIP_DUAL_APPROVAL_REQUIRED`. ADMIN users are allowed to execute skips.
- **Approver Roles Validation**: Step configuration updates validate that every entry in `approver_roles` exists in `roles.role_code` (case-insensitive); invalid entries raise 422 `LC_APPROVER_ROLE_UNKNOWN`.
- **Config Authorization**: `PUT /step-configs/{step_code}` requires `users.manage` permission rather than loose role strings.
