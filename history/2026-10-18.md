## BEX-T17: Settings API for System Parameters + Version-Check Hygiene

### 🎯 Objective
Resolve MAJOR findings `BEX-F32` and `BEX-F39` from `docs/plans/backend-review/be-cross-review.md`:
1. Provide a Settings API for system parameters under `modules/system_parameters/`:
   - `GET /api/v1/system-parameters`: requires `reports.view` permission; returns list of active system parameters with keys, values, descriptions, active state, update timestamp, and updater.
   - `PUT /api/v1/system-parameters/{key}`: requires `require_admin` role with payload `{param_value: str, justification: str (min 5 chars)}`; updates parameter and writes an `AuditLog` in one atomic transaction.
   - Typed validation per key:
     - Rates (`INSURANCE_RATE_*`, `INSURANCE_MARKUP`, `INSURANCE_TAX_RATE`, `INSURANCE_WAR_STRIKES_RATE`): float in `[0, 1]`.
     - `AIR_VOLUMETRIC_KG_PER_CBM`: float > 0.
     - Tiers (`*_TIERS`): JSON list of `{from_day: int >= 1, to_day: int | null, rate_per_day: float >= 0}` with contiguous days starting at 1.
     - Currency (`DD_DEFAULT_TARIFF_CURRENCY`): 3-letter currency code.
     - Non-negative numbers for fees, days, deemed percentages.
     - Unknown key -> 404 with code `SYSPARAM_UNKNOWN`.
     - Invalid value -> 422 with code `SYSPARAM_INVALID_VALUE`.
2. System & health hygiene:
   - In `main.py`, public `/health` endpoint drops database metadata leakage (`size_kb`, `tables_count`).
   - In `main.py`, `/api/v1/system/version-check` returns null fields and `check_status="unknown"` when `version.json` is missing or invalid, avoiding fabricated fallback version numbers.
