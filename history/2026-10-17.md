## BE03-T13: Declaration 46 and Banking Document Validation

### 🎯 Objective
Fix MAJOR findings BE03-F14 and BE03-F15 regarding Customs Declaration 46 and Banking Documents in `modules/import_documentation`:
1. **Declaration 46 (BE03-F14):**
   - Financial fields `total_cif_val_egp`, `total_customs_duties_egp`, `total_vat_egp` changed to `Optional[float] = Field(None, ge=0.0)`.
   - Non-null DB columns store `0.0` as fallback in repository when values are omitted without schema change.
   - Response model `CustomsDeclarationResponse` returns values as sent and adds `amounts_entered: bool`.
   - `acid_number` validated with `validate_acid_number(..., allow_pending=False)` (19 numeric digits required).
   - Validates that declaration `acid_number` matches linked `ImportFile.acid_number` when issued (raises 409 Conflict if mismatched).
   - Prevents duplicate active declaration drafts for the same file via `validate_no_duplicate_declaration_draft` (raises 409 Conflict).
2. **Banking Documents (BE03-F15):**
   - `currency_code` is required on creation and validated against active ISO currencies in `Currency` master table via `validate_currency_code` (raises 400 Bad Request if missing/inactive).
   - `doc_type` restricted to `Literal["Form 4", "Form 9", "Letter of Credit (L/C)"]`.
   - `BankingDocumentUpdate.amount` constrained to `Field(None, gt=0.0)`.
   - `receive_banking_document_service` rejects with 400 Bad Request if `received_date < request_date` (or `issue_date`).
