## 📝 2026-10-13 - Completed Task: Demurrage Date Sanity and EIR Step Guard (BE45-T10)

### 📌 Overview
- **Task Code:** `BE45-T10`
- **Description:** Implement chronological date validation against future dates for container gate-out and return milestones, require return dates in empty container return submissions, and guard import file lifecycle transitions so late EIRs cannot move files backwards on the board.

### 📁 Files Changed
- `modules/common/file_tracking.py` — Modified (added shared `file_past_step` and `_file_past_step`)
- `modules/demurrage_detention/schemas.py` — Modified (`empty_return_date` made required; added backward compatibility validator for `return_date`)
- `modules/demurrage_detention/validators.py` — Modified (added `today` check rejecting future `gate_out_date` or `empty_return_date`)
- `modules/demurrage_detention/service.py` — Modified (enforced `today=cairo_today()` across creation/updates/EIR, `today=None` for simulator; guarded lifecycle board advance with `_file_past_step`)
- `tests/unit/test_be45_dd_dates.py` — Created (comprehensive unit & router test suite for date bounds and step guards)

### 📊 Technical Changes
- **Date Sanity:**
  - `validate_demurrage_dates` now accepts `today: Optional[date] = None`. When provided, raises HTTP 422 if `gate_out_date > today` or `empty_return_date > today`.
  - Operational services (`create_demurrage_tracking_service`, `recalculate_and_update_tracking_service`, `update_single_container_service`, `record_empty_container_return_service`) pass `today=cairo_today()`.
  - The simulator (`simulate_demurrage_and_detention`) passes `today=None`, preserving what-if forecasting capabilities.
- **EIR Schema & Step Guard:**
  - `EmptyContainerReturnSubmit.empty_return_date` is now required without a default factory. A `@model_validator(mode="before")` maps legacy payload key `return_date` to `empty_return_date` when present.
  - In `record_empty_container_return_service`, both stage progress bump and follow-up lifecycle board step advancement (`advance_lifecycle_step_service`) are guarded by `not _file_past_step(imp_file, "STEP_20")`, ensuring files at `STEP_21` or beyond are not rolled back.
