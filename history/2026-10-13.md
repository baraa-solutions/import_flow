## 📝 2026-10-13 - Completed Task: Lock Sailed and Cancelled bookings (BE45-T12)

### 📌 Overview
- **Task Code:** `BE45-T12`
- **Description:** Enforce strict field-level locking rules on freight booking updates (PUT): Cancelled bookings are fully locked against modifications (409 Conflict), Sailed bookings only permit editing allowed fields (`notes`, `eta`, `vessel_name`, `voyage_number`, `status`) while locking B/L, ATD, costs, and containers (409 Conflict), Confirmed and Amended bookings lock `bill_of_lading_no`, `atd`, and `import_file_id` (409 Conflict), client re-sends of unchanged values succeed (200 OK), and container allocations are validated on update when `shipment_type` or `containers_data` is sent.

### 📁 Files Changed
- `modules/freight_booking/validators.py` — Modified (added `LOCKED_AFTER_CONFIRM`, `SAILED_EDITABLE`, `_items_match`, `_is_value_unchanged`, and `validate_editable_fields`)
- `modules/freight_booking/service.py` — Modified (called `validate_editable_fields` and `validate_container_allocation` on update in `update_booking_service`)
- `tests/unit/test_be45_booking_lock.py` — Created (comprehensive 9-test suite verifying Cancelled lock, Confirmed/Amended locks, Sailed locks, B/L retention, unchanged re-send acceptance, and container allocation validation)

### 📊 Technical Changes
- **Field Lock Constants & Rules:**
  - `LOCKED_AFTER_CONFIRM = frozenset({"bill_of_lading_no", "atd", "import_file_id"})`
  - `SAILED_EDITABLE = frozenset({"notes", "eta", "vessel_name", "voyage_number", "status"})`
  - Any update attempt on a Cancelled booking raises HTTP 409 Conflict.
  - On a Sailed booking, modifying any key outside `SAILED_EDITABLE` raises HTTP 409 Conflict.
  - On Confirmed or Amended bookings, modifying keys in `LOCKED_AFTER_CONFIRM` raises HTTP 409 Conflict.
- **Unchanged Value Detection (`_is_value_unchanged` & `_items_match`):**
  - Robust value matching compares stored database model attributes with submitted update payload values.
  - Correctly handles naive vs timezone-aware datetimes, float tolerances, string normalization, and list comparisons for container allocations and charge lines (skipping server-computed fields like `fx_rate_to_usd` and `amount_usd` when omitted by frontend).
  - Permits idempotent form re-submissions from frontend dialogs without false-positive 409 rejections.
- **Container Allocation Validation on Update:**
  - In `update_booking_service`, calls `validate_container_allocation(eff_type, eff_containers)` whenever `shipment_type` or `containers_data` is in `payload.model_fields_set`, rejecting Ocean FCL updates with empty container allocations (HTTP 400 Bad Request).
