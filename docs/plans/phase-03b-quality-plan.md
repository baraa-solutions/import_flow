## 2. Behaviour to keep identical

- ODC counters: `completion_percentage = round(verified/total*100, 1)`, `pending = total - received`, the auto-status ladder (verified → received → partial → draft), the auto-populate document list (9 items) with COO/inspection rules, the default couriers, and the order/columns of the Excel sheet.
- ODC orchestration on FULLY_*: ImportFile sync fields, `progress_percent` floor 75, `NA_CS01_ASSIGN_BROKER`, CS-01 task created once (3-day due date), STEP_11→STEP_12.
- Courier alert levels (≥5 CRITICAL, ≥3 WARNING), sorting, and the flat `tracking_url` per carrier (unless Q4 changes the threshold).
- DCA two-tier overall-status rules (l.218-223, l.264-271), the DC-04 document spec (keys, critical flags, Form 4 / B/L fallbacks), `completeness_percent`, and the "Critical Blocker" rule when open tickets exist. Lifecycle STEP_09→10 with progress floor 60.
- SDU: confidence thresholds 0.8 / 0.4, the notes text, `raw_text_preview[:500]`, entity verification (40-char `contains`), the 20 MB limit, magic-byte rules, and the cross-checker logic and Arabic output (only the English letter changes).

## 3. Characterization tests (first, green on current code)

## 5. Contract changes (for the Flutter agent)

1. 403 on the routes listed in DCA-02 / ODC-01 / SDU-01 for roles without the code.
2. DCA `MatrixCheckItem.status` gains `"Not Checked"`, and the fixed demo rows disappear. `overall_compliance` can no longer be "Fully Compliant" while a row is Not Checked.
3. DCA PUT `/{id}` ignores `commercial_status`, `customs_status` and `overall_status`. The review payloads' `reviewer_name`, the tickets' `resolved_by` and the sessions' `created_by`/`*_signoff_by` are ignored (server uses the logged-in user). Sessions: 409 `DCA_SESSION_FINAL_LOCKED`, 400 `DCA_SESSION_NOT_READY`.
4. ODC confirm-receipt: an unknown AWB gives 404 instead of appending a DHL row. Documents without a courier are no longer auto-received. Unknown status codes give 422. Malformed dates give 422.
5. ODC export path param = `import_file_id` only. New filename.
6. SDU `/apply/*` and `/cross-check` take typed bodies (same keys). Apply responses add `msg_code`/`params`. `/extract/*` enforces 415/413. `/parse-multi` is capped at 10 files.

## 8. Open CTO questions (safe default in brackets)

- **Q1** Should receipt of the originals auto-approve anything in DCA? [Commercial tier only, on FULLY_VERIFIED; the customs tier stays with the broker.]
- **Q2** Should confirm-receipt of an unknown AWB add the courier? [No: 404, so the user adds it on the session first.]
- **Q3** Can a final customs-approval session be reopened, and must open tickets block certification? [Final is locked; open tickets block; the lifecycle failure rolls back.]
- **Q4** Courier SLA: is DELAYED at 4 or 5 days? [Keep alerts 3/5, set the flat DELAYED to 5 so both views agree.]
- **Q5** Smart-upload parse/extract are used by master-data screens too. Keep them authentication-only, or add `smart_upload.use`? [Keep authentication-only (read-only extraction plus a log row); `/apply/*` and session delete get real permissions.]
- **Q6** For DCA statuses, store codes now (with a read-normalize of legacy labels), or labels until Flutter maps codes? [Validate against the code sets but keep storing and returning today's labels this wave; codes in the next wave with Flutter.]
