# Frontend review: execution checklist (TASKS)

Single source of truth for executing the 2026-10-05 frontend review. Master plan and rules: [README.md](README.md).
Order = wave, then severity, then phase. Wave 0 and Wave 1 may run in parallel: a Wave 1 task only waits for the Wave 0 task named in its *Depends on* column.
Status values: `todo`, `in-progress`, `review`, `done`, `blocked (<reason>)`. Update the Status cell in the same PR that does the task.

Legend: Sev `CRITICAL*` = report said MAJOR, lead raised it because it fixes a CRITICAL finding. *Backend needed* `yes: BE-xx` = the frontend task cannot finish before the backend item in README §6 is merged (backend-developer, not Antigravity); `optional` = the task works without it.

## How to execute a task

1. Pick the first `todo` row of the lowest open wave whose *Depends on* tasks are `done` and whose *Backend needed* is `no`, `optional`, or a `yes` item that is already merged.
2. Run `git status` and `git rev-parse --abbrev-ref HEAD`. Create one branch from the target branch the owner gives you: `fe/<task-id-lowercase>-<short-slug>` (for example `fe/fe06-t03-no-invented-cs-refs`). One task = one branch = one PR.
3. Open the report link. Read the whole task section, the finding rows it cites, and the files listed under *Files to change*. Read `AGENTS.md`, `.agents/rules/CORE_RULES.md`, `.claude/rules/flutter.md` and the `ui-screen-standards` skill first.
4. Apply the README §7 decisions (they override the report text where they differ, e.g. use `PagedDataTable` instead of `EnterpriseDataTable`, `/paginated` envelope instead of `X-Total-Count`).
5. Change only the files the task lists (plus the 3 l10n files and new test files). If you must touch another file, stop and write why in the PR.
6. Write the tests the task asks for. From `frontend/`: `flutter test <the new and touched test files>` and `flutter analyze <touched files>`. Both must be clean.
7. Check every acceptance-criteria box in the PR description, in Arabic (RTL) and English.
8. Set the Status cell of the task to `review` in this file in the same PR; the reviewer sets `done` after merge. Append one line to `history/YYYY-MM-DD.md` (append-only).
9. Track 1 only: no version bump, no `version.json`, no packaging, no edits to `.env`, `*.db` or `modules/**`.
